# V0.9.88B3 OOM 深度追查報告

## 結論

本輪找到至少一個**確定會跟歷史戰鬥／怪物重生次數一起線性增加**的 Runtime Leak，不只是圖片 Cache 推測。

### 已確認的線性 Leak：SkillEffectRuntime.lastHit

技能特效 Runtime 使用 `skillId + targetIdentity` 做 30ms 防重複播放，其中怪物 `targetIdentity` 優先使用每次 Spawn 都不同的 `_instanceId`。舊版會把每一組 key 寫入 `state.lastHit`，但只在換地圖、換角色或 pagehide 清空；同一張 MVP 地圖連續掛數千隻時不會 prune。

因此：

- 同一種 MVP 圖片可以只有一套；
- 但每次重生的怪物仍會產生不同 instance key；
- 技能打到新的 instance，就永久增加 Map entry；
- 長時間同圖掛機時，歷史擊殺數越高，Map 越大。

B3 修正為：

- `lastHit` 只保留 5 秒；
- hard cap 4096；
- safety poll 持續 prune；
- 增加 current / peak / pruned 診斷。

### 已修正的 bounded retention：latestTarget

每個技能還會保存最新目標 payload，其中包含 `targetObject`。它不是隨擊殺數無限增加（最多約技能數量），但可讓死亡怪物物件停留過久。B3 改為 5 秒後清除。

## 其他深查結果

### 世界怪物 Canvas backing store

本輪另外找到一個比「同一張 PNG 為何還會吃 RAM」更接近瀏覽器圖形層的風險：每個可見怪物都會建立自己的 `<canvas>`。Atlas 圖可以是共用的一份，但 Canvas 自己仍有獨立像素 backing store。舊版移除怪物時是 `element.remove()` + 把 canvas/context reference 設 null，是否立即歸還 backing store 由瀏覽器 GC/graphics allocator 決定。長掛時會重複建立／移除數千個 Canvas。

B3 在移除怪物元素前固定：

1. `clearRect`；
2. `canvas.width = 1` / `canvas.height = 1`；
3. 再移除 DOM 並清 context/reference。

這不會重載或破壞共用 Atlas，但能更主動把每隻怪物自己的 Canvas 緩衝區縮到最小。Profiler 新增 `canvasBackingReleases`。

### 背景分頁 / rAF throttle retention

深查還發現兩個「正常前景不一定出現，但分頁被瀏覽器 throttle 時可能擴大」的 retention：

- Skill Effect instance 原本主要靠 `requestAnimationFrame(render)` 移除過期效果。背景分頁的 rAF 可能暫停，而掛機 Timer 仍可能偶爾執行並建立新 effect instance。B3 改由 500ms safety poll 同步 prune 過期 instance，並加 256 hard cap。
- Monster Impact Batch 使用 `Set<monster>` 等下一個 rAF 才清空；若沒有 paint frame，Set 會抓住被命中的怪物物件。B3 加 120ms timer fallback、死亡目標 prune 與 128 hard cap。

### 世界怪物 / MVP Atlas

B2 已有：

- 22 種 MVP；
- MVP Atlas LRU；
- HTTP(S) 優先 ImageBitmap；
- 淘汰 ImageBitmap 時 `close()`；
- 2.5ms/frame 漸進 recycle；
- 死亡／離畫面清 DOM / Canvas / context / animation asset；
- stale async load generation 防止舊地圖資產回填。

B3 另加入 Entity / Element / ImageBitmap 建立、移除、釋放平衡計數。若未來仍 OOM，可直接看「Created - Removed」是否持續擴大。

### Reward / Death Queue

既有 V0.9.87I 已改用 slim death reward snapshot，不把 Canvas / DOM / Atlas 等 monster runtime 引用塞進 Reward Queue；queue 會 drain。未找到同擊殺數線性成長的明確證據。

### Damage Number / Combat Visual

Queue 已有限額，DOM 與 active sequence 有 timeout cleanup；B2 另有 stale cleanup。B3 增加 `getCombatVisualRuntimeStats()`，讓 AFK 診斷記錄 current queue / active sequences / damage DOM / reward queue。

### Ground Effects

Effect 有 duration/maxTicks，完成後會從 manager 移除；目前未找到明確永久累積。B3 將 active effects / targetHitEntries 納入 AFK profiler。

### 掉落物 / Inventory

一般同 Item ID 掉落會在 inventory stack 上增加 count，不會每次掉落都新增 inventory row。裝備在某些 normalize/reload 流程可能展開為 equipment instances，屬於長期背包膨脹風險，但不是本輪同分頁 8,000 擊殺 OOM 的最強解釋；B2 30 分鐘自拆可降低此壓力。

### Mercenary Runtime

最多 3 名，AI interval 固定、visual rAF 單一、解散會清 interval / DOM / visual refs；動畫共用 Cache 有上限。未找到與怪物擊殺數線性成長的路徑。

### Chat / 其他長壽集合

玩家聊天 `state.seen` 原本會把每個已見 message ID 留到頁面關閉。它不是朋友 OFFLINE MVP 掛機的主因，但同樣屬於無界集合；B3 改為最多 512 筆。其他本輪檢查到的狀態配點 pending Map、Reward audit、Damage queue、世界 respawn queue 等都有清空／上限／drain 路徑。

### Legacy Monster Atlas

舊式非世界串流地圖的 singleton atlas cache 原本沒有上限。它不是目前 MVP 世界串流 8,000 擊殺的主因，但可能讓玩家跨不同舊地圖後累積怪物種類。B3 加 12-entry LRU。

## B3 Leak Profiler 驗收方式

長掛理想狀況：Created 可以一直增加，但 Live/Active 應維持平台。重點觀察：

- Live monster entities / elements
- Entity created - removed balance
- ImageBitmap created / recycled balance
- Skill effect `lastHitEntries`（應維持很小，不再跟 kills 成長）
- `latestTargetEntries`
- Active skill effects
- Damage DOM / active sequences
- Ground effects
- Reward queue
- Mercenary live DOM / assets
- Inventory rows / equipment instance rows

如果 B3 仍在某個擊殺數 OOM，最後一份 AFK heartbeat 就能指出哪一類 Active 數量還在上升，供下一版抓第二個 Leak。

## Starter Asset Gate

初學者修練場 Starter Pack 會預先快取必要 bytes，但不大量 predecode。Common 約 2.9 MB，加當前性別約 0.6 MB。即使 8 種新手怪 Atlas 若全部 decoded 會比檔案尺寸大很多，B3 因此只 predecode 當下地圖背景與目前初學者 Idle 圖；怪物 Atlas 進入 Runtime 後才按需求解碼。
