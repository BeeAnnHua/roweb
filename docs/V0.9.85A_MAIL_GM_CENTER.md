# RO_WEB V0.9.85A — 遊戲內信箱 / GM CENTER Phase 1

基準：V0.9.84C（roweb 註冊網頁完成版）

## 新增

- 帳號共用遊戲內信箱，右上功能列新增「信箱」。
- 未讀數量徽章、全部 / 未讀 / 可領附件篩選。
- 郵件可包含最多 5 種道具與 Zeny。
- 附件由目前登入角色領取。
- 領取採 `begin claim -> 本機收據 -> 角色雲端存檔驗證 -> finalize claim`，避免普通重試造成重複領取。
- GM 帳號右上功能列會顯示「GM」，可進入 `gm_center.html`。
- GM CENTER 使用既有 Supabase Auth Session，不另建 GM 密碼。
- GM CENTER 寄送目標：指定 Player ID / 全服啟用帳號 / 一般玩家 / GM・測試帳號。
- 玩家查詢只顯示 Player ID、遊戲帳號、狀態、測試標記、角色權限；不暴露 Email。
- 最近寄送紀錄以 batch 彙整。

## 必做：Supabase SQL

在 Supabase Dashboard -> SQL Editor 執行：

`supabase/V0.9.85A_MAIL_GM_CENTER.sql`

此 SQL 會建立：

- `public.ro_mail_messages`
- RLS：玩家只能 SELECT 自己 RO account 的郵件
- `ro_mail_mark_read`
- `ro_mail_begin_claim`
- `ro_mail_finalize_claim`
- `ro_gm_find_players`
- `ro_gm_send_mail`
- `ro_gm_recent_mail`

GM RPC 內部會再次核對目前 Auth User 是否擁有 `account_role='gm'` 且 `account_status='active'` 的 RO account。前端隱藏按鈕不是權限防線。

## 測試順序

1. 執行 SQL，確認無 error。
2. 覆蓋 Patch 檔案並用 HTTP server 啟動。
3. 一般玩家登入 Player ID 100010，確認右上有「信箱」、沒有「GM」。
4. GM01 / Player ID 100001 登入，確認右上同時有「信箱」與「GM」。
5. GM CENTER 搜尋 100010，寄一封無附件郵件。
6. 100010 打開信箱，確認未讀徽章、讀信後未讀數下降。
7. GM 寄 Item ID 501 x3 + Zeny 1000。
8. 玩家領取，確認背包 +3 紅色藥水、Zeny +1000，並顯示已領取。
9. 重新整理後再次開信箱，確認同封郵件不能重複領取。
10. GM 測試「一般玩家」或「全服」小範圍後再正式使用。

## 保留不變

V0.9.84C 的 Email OTP、1 Email 最多 5 RO 帳號、Player ID 100010 起跳、12 角色槽、角色雲端存檔 / localStorage / IndexedDB 安全備份邏輯不變。
