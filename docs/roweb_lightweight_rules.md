# RO_WEB 輕量化設計規則

版本：v0.2 起適用

RO_WEB 的方向不是完整模擬 RO 官方原版，而是「保留 RO 靈魂的網頁放置版」。
核心原則：保留收集、養成、職業、技能、地圖、怪物、掉寶；移除只增加操作成本、但不增加遊戲樂趣的繁瑣限制。

---

## 一、永久保留的 RO 核心

- Base Lv / Job Lv
- Base EXP / Job EXP
- Zeny
- 地圖與怪物分布
- 怪物掉寶
- 背包與物品堆疊
- 裝備
- 技能
- 卡片
- NPC / 商店 / 任務
- Boss / MVP
- 圖鑑與收藏感

---

## 二、永久簡化或不做的系統

### 1. 不做負重量

RO_WEB 不做：

- 負重上限
- 超重懲罰
- STR 影響負重
- 物品重量計算

背包只記錄：

```json
{
  "itemId": 501,
  "count": 12
}
```

---

### 2. 不分已鑑定 / 未鑑定

RO_WEB 不做：

- 未鑑定物品
- 放大鏡
- 未鑑定名稱
- 問號圖示
- 鑑定 NPC
- identified / unidentified 兩套資料

打到裝備後，直接顯示正式名稱、能力與圖片。

例如：

```text
打到 短劍
→ 背包直接顯示 短劍
→ 可直接裝備
```

---

### 3. 不做箭矢消耗

RO_WEB 不做：

- 箭矢數量
- 買箭
- 換箭
- 箭矢用完不能攻擊
- 屬性箭消耗

弓箭手與獵人系職業預設永久可遠距攻擊。

---

### 4. 不做技能媒介消耗

RO_WEB 不做過於麻煩的技能材料消耗。

例如：

- 技能特殊材料
- 一次性施法媒介
- 複雜箭矢 / 寶石 / 材料限制

保留：

- SP
- 技能 SP 消耗
- 技能冷卻或簡化延遲

---

## 三、Buff 技能規則

已學會的 Buff 類技能，可以在技能或自動設定面板中勾選「自動維持」。

例如：

```text
☑ 天使之賜福：自動維持
☑ 加速術：自動維持
☑ 集中力向上：自動維持
```

系統邏輯：

```text
玩家已學會 Buff 技能
        ↓
玩家勾選自動維持
        ↓
戰鬥 / 掛機期間自動檢查 Buff 狀態
        ↓
Buff 消失或快結束時，自動施放
        ↓
消耗 SP，但不消耗額外材料
```

### Buff 自動維持原則

- 只有「已學會」的 Buff 技能可以勾選。
- 沒學會的技能不可勾選。
- SP 不足時暫停施放。
- SP 恢復後可再次自動施放。
- 不消耗技能媒介材料。
- 不需要玩家手動一直按。

---

## 四、消耗品規則

消耗品保留，但簡化操作。

例如：

- 紅色藥水：恢復 HP
- 藍色藥水：恢復 SP
- 蝴蝶翅膀：回城或回安全點
- 蒼蠅翅膀：換怪 / 換位置 / 隨機移動，可視後續設計調整

未來可以加入自動使用設定：

```text
HP 低於 50% → 自動使用紅色藥水
SP 低於 30% → 自動使用藍色藥水
HP 低於 20% → 自動回城
```

---

## 五、資料與 ID 規則

RO_WEB 使用官方 RO ID 作為唯一主要 ID。

### Item

```text
紅色藥水 = 501
橙色藥水 = 502
波利蛋 = 9001
```

圖片輸出：

```text
images/items/501.webp
images/items/502.webp
images/items/9001.webp
```

JSON：

```json
{
  "id": 501,
  "name": "紅色藥水",
  "image": "501.webp"
}
```

### Monster

怪物也使用官方 Monster ID。

圖片輸出：

```text
images/monsters/1002.webp
```

## 六、RO Studio 與 RO_WEB 分工

RO Studio 負責把官方資料轉成 Web 可用資料。

```text
官方 DB / LUB / BMP / SPR / ACT
        ↓
RO Studio Builder
        ↓
JSON + WebP
        ↓
RO_WEB
```

RO_WEB 不直接處理原始亂碼資源名，只讀整理好的資料。

例如 Item Builder 未來規則：

```text
itemInfo_UTF8.lub
        ↓
取得 itemId / name / resourceName
        ↓
搜尋來源圖片
        ↓
輸出 images/items/501.webp
        ↓
產生 data/items.json
        ↓
找不到圖片則寫入 missing_items.json
```

## 七、設計判斷標準

每次新增功能時，先問：

> 這個功能是讓遊戲更好玩，還是只是更像官方原版？

如果只是更像官方原版，但會讓網頁版變麻煩，就優先簡化或不做。

RO_WEB 的目標：

> 保留 RO 的收集、養成、掉寶、職業與世界觀，把繁瑣操作交給系統。
