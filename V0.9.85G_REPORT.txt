Root cause confirmed:
1. ro_web_account_profile_local_backup_v1 was global and retained after the first migration.
2. Older offerLocalMigration logic only compared migratedToAccountId to the CURRENT account, so another Player ID could be offered the same legacy backup again.
3. That path inserts new ro_characters rows, which explains duplicated characters after account switching / cloud pull.
4. V0.9.85F also modified core JS files without bumping all corresponding index.html ?v cache keys, so normal reloads could keep stale code.

V0.9.85G:
- one-shot migration backup (consumed after success)
- migration target lock (targetAccountId)
- no automatic migration into accounts that already have cloud characters
- ambiguous old V1 backups are never auto-imported
- cloud accounts cannot be mistaken for local migration sources
- core cache keys bumped to 0.9.85G
