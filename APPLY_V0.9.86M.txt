彼岸花仙境 V0.9.86M — 舊版未命名角色救援補強（累積 H / I / J / K / L）

用途
- 修正 Legacy 救援器過去把「沒有 player.name」的舊角色直接排除的盲點。
- 保留 H/I/J/K/L 全部救援能力、完整 Email 顯示與安全限制。

安裝
1. 將本 Patch 內容覆蓋到目前 RO_WEB / GitHub Pages 專案根目錄。
2. 不需要新增 Supabase SQL；沿用已安裝的 V0.9.86I_LEGACY_BROWSER_CHARACTER_RESCUE.sql。
3. 等 GitHub Pages 部署完成後 Ctrl+F5。
4. 朋友重新登入 Player ID 100011，先只觀察候選畫面，不要急著復原。

V0.9.86M 新增
- 無名稱舊角色只要「已有實際進度 + player 結構完整度 >= 4」也可列為完整候選。
- 未命名候選顯示：【未命名角色】/ 職業 / Base / Job / 建議 SLOT / 完整度。
- 正式復原前必須輸入新的角色名稱（1–12 字），再寫入 save_data.player.name 後才呼叫既有安全 RPC。
- writer_lease / pending_writer_lease / persist / session 控制資料仍不可成為角色候選。
- 原 localStorage / sessionStorage / IndexedDB 一律不刪除。
- 另一個 Supabase account UUID 的存檔仍禁止跨帳號復原。

測試重點
- SLOT 2 / 3 / 4 原本三個完整候選必須繼續存在。
- 如果 SLOT 1 十字軍其實是舊版未命名角色，這版應新增一個「【未命名角色】」完整候選。
- 若找到未命名角色，先截圖確認職業/Base/Job/SLOT，再決定是否復原。
