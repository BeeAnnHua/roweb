ROOT CAUSE — REPRODUCED
----------------------------------------
The GO build was reproduced with a Lv275 Cardinal save containing an active,
overdue "持續祈療 / Mediale Votum" periodic-heal buff.

GO result:
- Save JSON parsed successfully.
- Startup then failed with: Maximum call stack size exceeded.
- Stack repeatedly re-entered:
  normalizeActiveBuffs -> calculateDerivedPlayerStats ->
  getActiveBuffBonusTotals -> normalizeActiveBuffs.

Cause:
- The periodic heal needs derived INT/MATK.
- Active-buff bonus aggregation was also calling normalizeActiveBuffs(), which
  executed the overdue periodic heal again while derived stats were being built.

GP FIX
----------------------------------------
1. Active-buff stat aggregation now uses:
   normalizeActiveBuffs({ processPeriodic: false })
2. Save loading only cleans/normalizes buffs; it does not run overdue periodic
   heal, SP drain, pulse, or other tick-side effects during boot.
3. Normal runtime normalizeActiveBuffs() still executes periodic effects after
   startup, so Mediale Votum healing remains functional.
4. Auto-combat numeric controls are owned by the existing compact auto panel.
   The global black-gold number runtime skips those inputs, eliminating double
   wrappers on Cardinal's many auto-buff threshold rows.
5. Dynamic black-gold UI audits are batched once per animation frame.
