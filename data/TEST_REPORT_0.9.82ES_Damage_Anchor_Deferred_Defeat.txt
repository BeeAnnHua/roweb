RO_WEB 0.9.82ES Test Report
============================================================
Scope
- Damage number anchoring on streamed world monsters
- Monster HP bar compositor update
- Deferred and batched defeat rewards / drops / UI / save
- Existing spatial targeting and all-skill runtime regression

Root-cause verification
1. Damage numbers were queued without a stable target position. If the target died or currentMonster was cleared before RAF flush, the renderer used a shared fallback coordinate.
2. The visible stutter correlated with normal monsters dying, not with 1-damage plants. The synchronous defeat path granted EXP/Job/Zeny, rolled drops, rebuilt inventory/log UI and wrote localStorage before the next paint.
3. HP fill width updates and repeated DOM lookup added avoidable layout work, but were not the dominant pause.

Implemented
- Snapshot target top-center coordinates when damage is queued.
- Cache HP bar/fill DOM references and update with transform: scaleX().
- Queue defeat resolution; apply death state immediately and defer heavy reward packages until after paint.
- Batch reward logs, player UI, inventory UI and save requests.
- Avoid hidden legacy monster UI rebuild for streamed world entities.
- Limit damage-number DOM creation to 18 nodes per frame.
