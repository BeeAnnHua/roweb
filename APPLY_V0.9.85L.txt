跨裝置雲端角色存檔 RPC 修正

【為什麼需要這版】
V0.9.85K 已成功阻止「雲端載入失敗時用 Lv1 初學者覆蓋角色」，但測試確認 Supabase 回覆：
permission denied for table ro_characters

原因是瀏覽器前端不應直接 UPDATE ro_characters。
V0.9.85L 改由安全 RPC 寫入，RPC 會驗證 auth.uid()、account_id、character_id 三者歸屬。

【安裝順序】
1. Supabase → SQL Editor → New query
2. 貼上並執行：supabase/V0.9.85L_CLOUD_CHARACTER_SAVE_RPC.sql
3. 確認顯示 Success. No rows returned
4. 再覆蓋本 Patch 的遊戲檔
5. Ctrl+F5

【重要測試】
A. 先在目前還保有正確 Lv240 基因資料的本機瀏覽器登入。
B. 選該角色進遊戲；應成功把正確進度同步到 Supabase，不再出現 permission denied。
C. 手動存檔一次，確認不再顯示「雲端同步未完成」。
D. 再用 GitHub Pages / 無痕視窗 / 另一瀏覽器登入同一帳號。
E. 應讀到同一隻 Lv240 基因，而不是 Lv1 初學者。
